# /design — 분석 설계서 작성

분석가가 바로 분석을 수행할 수 있을 정도의 상세한 분석 설계서 초안을 작성합니다.

## 실행 흐름

### 1단계: 정보 수집
AskUserQuestion을 사용하여 순서대로 확인:

1. **분석의 주요 목적과 배경은 무엇인가요?**
2. **기획서나 이벤트 명세를 이미 구조화했나요?** (/read-spec 결과가 있으면 경로 확인)
3. **검증하고 싶은 가설이 이미 있나요?** (있으면 공유 요청, 없으면 함께 수립)
4. **분석 기간은 어떻게 되나요?**
5. **특별히 관심 있는 유저 세그먼트가 있나요?**

### 2단계: 이벤트 매핑 (필요 시)
기획서와 이벤트 명세가 있는 경우, `event-mapper` 에이전트를 호출:

```
Agent(subagent_type="event-mapper", prompt="[기획서 요약 + 이벤트 명세 + 분석 목적]")
```

매핑 결과를 사용자에게 **먼저 확인**받을 것.

### 3단계: 분석 설계서 초안 작성
`analysis-designer` 에이전트를 호출:

```
Agent(subagent_type="analysis-designer", prompt="[수집한 모든 정보 + 이벤트 매핑 결과]")
```

설계서에 반드시 포함:
- 가설별 분석 방법
- 지표 정의 (**수식 수준**)
- 세그먼트 정의
- 결과에 따른 해석 가이드 ("결과 A이면 → X를 의미")
- **분석 우선순위** (🔴핵심 / 🟡중요 / 🟢보조)
- 예상 결과물

### 4단계: 가설 단위 리뷰
- 가설을 **하나씩** 사용자에게 보여주고 피드백 수집
- 수정사항 반영
- 모든 가설 확인 후 최종 설계서를 .md 파일로 저장

### 5단계: 후속 안내
- **쿼리 작성이 필요하면** → `/query`
- **바로 코드 생성이 필요하면** → `/analyze`

## 주의사항
- 사용자가 이미 정의한 가설이나 지표 분류가 있으면 **반드시 반영**.
- **모니터링 지표와 분석용 지표를 구분**할 것.
- 해석 가이드는 "결과 A이면 → X를 의미" 형태로 구체적으로.
