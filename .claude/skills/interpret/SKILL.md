# /interpret — 분석 결과 해석

분석 결과를 해석하고, 가설 검증 여부를 판단하며, 추가 분석 방향을 제안합니다.

## 결과 공유 방식 (우선순위 순)

1. **PNG 파일 경로** — 테마별 폴더(`thema{N}_fig/`)에 저장된 이미지 경로를 알려주는 방식. 가장 빠르고 ipynb를 읽지 않아도 됨. `/viz`로 생성한 코드에 savefig가 포함되어 있으면 이 방식 사용.
2. **텍스트 수치 직접 복붙** — print 출력 결과를 채팅에 붙여넣기.
3. **ipynb 직접 읽기** — 위 두 방식이 모두 불가할 때만 사용. 컨텍스트를 많이 소모하므로 최후 수단.

> 아직 savefig 코드가 없다면 해석 전에 `/viz`에서 먼저 추가할 것.

## 실행 흐름

### 1단계: 정보 수집
사용자가 이미 결과를 공유했으면 AskUserQuestion 없이 바로 2단계로 진행.
공유된 정보가 부족할 때만 AskUserQuestion으로 확인:

1. **결과 공유 방식** — 위 우선순위 참고. PNG 경로 또는 텍스트 수치 복붙 권장.
2. **원래 가설은 무엇이었나요?** (분석 설계서 경로 또는 직접 설명)
3. **비즈니스 맥락이 있나요?** (기능 출시일, 프로모션 기간, 외부 이벤트 등)
4. **특별히 궁금한 포인트가 있나요?**

### 2단계: 결과 해석
`result-interpreter` 에이전트를 호출:

```
Agent(subagent_type="result-interpreter", prompt="[분석 결과 + 가설 + 비즈니스 맥락]")
```

해석에 포함:
- 핵심 수치 요약 (표)
- 가설 검증 결과 (✅ 지지 / ❌ 기각 / ⚠️ 부분적 지지)
- 주요 인사이트
- 주의사항 (표본 크기, 외부 변수 등)
- 추가 분석 제안 (우선순위별)

### 3단계: 해석 결과 검토
- 사용자에게 해석 결과를 보여주고 피드백 수집
- 추가 분석이 필요하면 방향 안내

### 4단계: 후속 안내
- **추가 코드 수정** → `/analyze`
- **시각화 추가** → `/viz`
- **보고서 작성** → `/report`

## 주의사항
- **데이터에 없는 내용을 추측하지 말 것.** 추가 확인이 필요하면 추가 분석으로 연결.
- 인과관계와 상관관계를 구분.
- 해석의 **확신 수준**을 명시 (강한 근거 vs 추가 확인 필요).
