# /read-spec — 문서 읽기 & 구조화

기획서(PDF)나 Firebase 이벤트 명세(CSV)를 읽고, 분석에 필요한 정보만 추출·구조화합니다.

## 실행 흐름

### 1단계: 정보 수집
AskUserQuestion을 사용하여 다음을 확인:

- **어떤 문서를 읽을 건가요?** (파일 경로 — PDF 기획서, CSV 이벤트 명세, 또는 둘 다)
- **전체를 구조화할 건가요, 특정 부분만 필요한가요?** (예: 특정 기능, 특정 화면 관련만)
- **이미 /read-spec을 실행한 다른 문서가 있나요?** (기획서와 명세를 매칭할 때 필요)

### 2단계: doc-reader 에이전트로 문서 처리
`doc-reader` 에이전트를 호출하여 문서를 구조화합니다.

```
Agent(subagent_type="doc-reader", prompt="[수집한 정보 포함하여 구조화 요청]")
```

**PDF 기획서의 경우:**
- 기획 배경, 주요 기능, 사용자 플로우, 성공 기준 추출

**CSV 이벤트 명세의 경우:**
- 카테고리별 이벤트 그룹핑 (홈 화면, 출석체크, 온보딩 등 원본 카테고리 유지)
- ep_event_label, 설명, 주요 파라미터 정리
- 이벤트 간 관계/흐름 식별

### 3단계: 결과 저장 및 확인
- 구조화된 결과를 마크다운 파일로 저장 (파일명 제안)
- 사용자에게 결과를 보여주고 확인 요청
- 누락이나 수정이 필요한 부분 피드백 반영

### 4단계: 후속 안내
구조화가 완료되면 다음 단계를 안내:
- **이벤트 매핑·분석 설계가 필요하면** → `/design`
- **바로 쿼리가 필요하면** → `/query`

## 주의사항
- 원본 문서 전체를 그대로 출력하지 말 것. 핵심만 구조화.
- 이벤트 명세가 큰 경우, **카테고리 목록을 먼저 보여주고** 사용자가 필요한 카테고리를 선택하게 할 것.
- 구조화 결과는 이후 /design, /query 등에서 활용되므로 정확성이 중요.
